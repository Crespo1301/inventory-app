# App Store Requirements

What it takes to ship this app to the Apple App Store and Google Play — both
equal-priority targets as of 2026-08. Treat this as a living checklist —
update it as items are completed. See `docs/launch-roadmap.md` Phase 0 for
the CSolutions entity-formation chain both accounts below depend on.

## 1. Accounts & Programs

Both enrolling as **Organization** (CSolutions), not Individual — this is
blocked until CSolutions is a formed LLC with an EIN and a D-U-N-S number
(`docs/launch-roadmap.md` Phase 0). Organization enrollment also skips
Google's 12-tester/14-day closed-testing gate that applies to personal
accounts, and matches the existing `com.csolutions.inventoryapp` bundle ID.

- [ ] **Apple Developer Program** — $99/year. Org review typically runs
      1–2 weeks after the D-U-N-S number is in hand. Required to build,
      sign, and submit.
- [ ] **App Store Connect** — create the app record (bundle ID, name, primary
      category: *Business* or *Food & Drink*).
- [ ] **Google Play Console** — $25 one-time registration. Org verification
      (business documents + D-U-N-S + government ID + a live business
      website checked via Search Console) typically takes 1–7 days once
      documents are submitted.
- [ ] **Google Play data safety form** — Android's equivalent of Apple's App
      Privacy "nutrition label" (section 3 below); same underlying data
      declarations (account email, restaurant/inventory data), different form.

## 2. Build & Submit Pipeline

The app uses Expo, so builds go through **EAS Build** and **EAS Submit**:

- [x] `eas.json` configured with `development`, `preview`, and `production`
      profiles.
- [x] iOS bundle identifier set (`com.csolutions.inventoryapp`) in
      `app.config.ts` → `ios.bundleIdentifier`.
- [x] Android `package` set in `app.config.ts` → `android.package`.
- [x] App version + build number strategy — `eas.json` uses
      `appVersionSource: remote` with `autoIncrement` on production.
- [ ] First builds go to **TestFlight** (iOS) and **internal testing** (Android)
      before any public release.

## 3. Privacy — the most common rejection area

- [x] **Privacy policy** — written and finalized (pending hosting) at
      `docs/privacy-policy.md`. Covers collected data (account email,
      restaurant/inventory data), Supabase as infrastructure processor, RLS
      security, and in-app account deletion.
- [ ] **Privacy policy URL** — the in-app link is now wired (Account → Privacy
      Policy, pointing at the `PRIVACY_POLICY_URL` constant in
      `constants/app-meta.ts`). Remaining: publicly host the policy in
      `docs/privacy-policy.md`, paste the live URL into the `PRIVACY_POLICY_URL`
      constant, and enter the same URL in App Store Connect.
- [ ] **App Privacy details** ("nutrition label") in App Store Connect — declare
      collected data: *Contact Info → email*, *User Content* (inventory/order
      data linked to the account). We do **not** track users or run ads.
- [ ] **Privacy manifest** (`PrivacyInfo.xcprivacy`) — Expo SDK 54 generates a
      baseline; declare reasons for any required-reason APIs used by our
      dependencies. Verify after the first production build.
- [ ] **App Tracking Transparency** — not required; the app does no cross-app
      tracking. Do not add tracking SDKs without revisiting this.

## 4. Account Requirements

- [x] **In-app account deletion** — done. Account screen → "Delete Account"
      removes the profile and auth user; when the last member of a company
      leaves, the company and all its data are removed too.
- [ ] **Sign in with Apple** — only required if we offer third-party social
      login. We use email + password only, so it is **not required**. If a social
      login is ever added, Sign in with Apple must be added alongside it.

## 5. Metadata & Assets

- [x] **App icon** — 1024×1024 PNG, square corners. Final clipboard-and-check
      mark in `assets/images/icon.png`, generated by `scripts/make-icon.js`.
      EAS flattens the alpha channel for the store build.
- [ ] **Screenshots** — 6.9" iPhone base size **1320×2868 px**, flattened PNG/JPG,
      RGB, no alpha. The app is iPhone-only (`supportsTablet: false`), so **no
      iPad screenshots are required**.
- [ ] App name, subtitle, description, keywords, support URL, marketing URL —
      support/marketing URLs resolve once the marketing site
      (`docs/launch-roadmap.md` Phase 5) is live; listing copy is drafted in
      `docs/app-store-listing.md` and doubles as the Play Store listing source.
- [ ] **Age rating** questionnaire (this app rates 4+).
- [x] **Export compliance** — the app uses only standard HTTPS encryption.
      `ITSAppUsesNonExemptEncryption: false` is declared in `app.config.ts` →
      `ios.infoPlist`, so no per-submission declaration is needed.

### Android-specific assets (Google Play)

- [ ] **Feature graphic** — 1024×500 px, required for the Play Store listing
      (no iOS equivalent).
- [ ] **Phone screenshots** — at least 2, from a real Android device/emulator.
- [ ] **Short description** (80 chars) and **full description** (4000 chars) —
      can share source copy with `docs/app-store-listing.md`.
- [x] **Adaptive icon set** — foreground/background/monochrome layers already
      generated by `scripts/make-icon.js`, declared in `app.config.ts` →
      `android.adaptiveIcon`.
- [ ] **Content rating questionnaire** (Google's own, separate from Apple's
      age rating).
- [ ] **Data safety form** — see section 1.

## 6. Quality Gates (App Review)

- [ ] No crashes, no broken flows; reviewers must be able to use it end to end.
- [ ] Provide a **demo account** (admin + a manager) in App Review notes — the
      app is useless without a signed-in account, so reviewers need credentials.
- [ ] If "Confirm email" is enabled, the demo account must already be confirmed.
- [ ] Every screen must work without placeholder/Lorem content.
- [ ] Minimum iOS version follows Expo SDK 54 (currently iOS 15.1+).
