# Launch Roadmap

The goal: a universal restaurant ordering app on the App Store, Google Play,
and the web, backed by a public marketing site, growing into a paid product
with subscription tiers. As of 2026-08, iOS and Android are equal-priority
targets — Android is no longer secondary.

## Phase 0: CSolutions Entity Formation (blocking, as-soon-as-possible)

Both the Apple Developer Program and Google Play Console require an
**Organization** enrollment to be a real, verifiable legal entity. CSolutions
is not one yet. This phase blocks Phase 3's Organization enrollment step for
both stores and is tracked in
`/home/cresp3/Portfolio/business/compliance-register.csv`, not in this repo.

- WA LLC formation → EIN (IRS, free, same-day once the LLC is approved) →
  D-U-N-S number (Dun & Bradstreet, free, budget 5–28 days).
- Google's org verification also checks a live business website via Search
  Console — this depends on Phase 5 (Marketing Site) existing first.
- Not a hard deadline. Start immediately; everything downstream (Apple org
  review, Google org verification) waits on the D-U-N-S number, which is the
  long pole in this chain.

## Phase 1: Working Product (current)

Prove the app is faster and more reliable than a whiteboard.

- Company / location / FOH-BOH structure.
- Admin, manager, and team-member roles with scoped access.
- One-tap low-stock capture.
- Item catalog with par levels, units, and pack sizes.
- Explainable order suggestions, manager verification, and export/share.
- Supabase backend with authentication, row-level security, and realtime sync.
- Invite flow for managers and team members.

## Phase 2: Real-Kitchen Testing

Install on real devices and run a full order cycle.

- EAS build config is done (`eas.json` with development/preview/production
  profiles); `app.config.ts` is variant-aware. Remaining: run the builds and
  push to TestFlight / internal testing.
- Test across multiple roles and at least two locations.
- Capture feedback after every order day and tighten the capture flow.
- Add an offline write queue so capture survives bad kitchen Wi-Fi.

## Phase 3: Store Preparation — parallel iOS + Android tracks

Both platforms build from the same EAS/Expo pipeline already configured in
this repo — no Mac or Android Studio required, EAS Build compiles both in the
cloud. See `docs/eas-build.md` and `docs/app-store-requirements.md`.

**iOS**
- App name and icon are done — the final icon mark is generated by
  `scripts/make-icon.js`. Remaining: screenshots from real screens.
- Privacy policy is written and finalized (`docs/privacy-policy.md`) with an
  in-app link wired on the Account screen — still needs public hosting
  (Phase 5 provides the domain).
- Demo account for App Review notes.
- Internal or closed testing first (TestFlight).

**Android** (new parallel track)
- Play Console org enrollment skips the 12-tester/14-day closed-testing gate
  that applies to personal accounts — one more reason Organization enrollment
  (Phase 0) is worth the wait over Individual.
- Needs its own store assets: feature graphic, phone screenshots, short/full
  description (can share source copy with iOS via `docs/app-store-listing.md`
  once genericized), content rating questionnaire, data safety form
  (Android's equivalent of Apple's App Privacy "nutrition label").
- `app.config.ts` already declares `android.package` and the adaptive icon
  set; no Android-specific code changes are expected beyond store assets.

**Both platforms need, before submission**
- Support URL and marketing URL — currently open items, resolved by Phase 5.
- Google's org verification and Apple's org review both check the same
  public business site.

## Phase 4: Web App (Expo web export)

Decision: reuse the existing Expo/React Native codebase's web export rather
than building a second, separate web app. `app.config.ts` already sets
`web.output: 'static'` — `npx expo export -p web` produces a static bundle
deployable to any static host, targeted at `app.<domain>`.

- **Responsive pass** — every screen today is built mobile-first (large
  touch targets, single-column stacks, per `docs/ios-design-guidelines.md`).
  Needs real breakpoint/layout work for desktop browsers across Home, Stock,
  Order Planner, Analytics, and Manage — not a rebuild, but not free either.
- **Auth on web** — verify Supabase Auth's web session handling works
  cleanly through Expo Router's web output; don't assume it matches the
  native flow untested.
- **Native-only API audit** — `expo-haptics`, `expo-symbols` (SF Symbols),
  and the native offline-queue behavior need confirmed web fallbacks. Most
  already degrade gracefully via the existing `Icon` component pattern, but
  this needs a screen-by-screen audit, not a guess.
- **Deploy target** — a static export works on Vercel/Netlify/Cloudflare
  Pages; Vercel matches this workspace's existing patterns.

## Phase 5: Marketing Site

Decision: a standalone repo, deployed at the bare `<domain>` (the web app
lives at `app.<domain>`), not routes inside this Expo app. Keeps app releases
decoupled from marketing changes and gives Apple/Google org verification a
real site to check.

- Seed copy from `docs/app-store-listing.md` (name, subtitle, keywords,
  description already drafted there).
- Provides the support URL and marketing URL both stores require.
- Should exist and be live *before* Phase 0's org verification steps run,
  since Google checks it directly via Search Console.
- Tracked in its own repo, not this one — see that repo's own docs for
  build/deploy details once scaffolded.

## Phase 6: Paid Tiers

Once the product is proven in real kitchens:

- Subscription tiers are defined — Starter / Pro / Multi-Location, in
  `src/domain/billing.ts` — and surfaced on the in-app Plan & Billing screen
  (Account → Plan & billing) with live usage meters against plan limits.
- Gating math (locations, team size, history retention) is implemented; limits
  are **not enforced** yet — every company runs with full access until billing
  ships.
- Remaining: wire real billing, add the `companies.plan` column, and enforce
  limits. Invite emails delivered through a backend function.

## Cost Notes

- Washington LLC: $200 online filing ($180 + $20 processing), ~5 business
  days standard or +$100 for 3-business-day expedited; $70 WA annual report
  thereafter.
- EIN: free (IRS.gov, same-day once the LLC is approved).
- D-U-N-S number: free (Dun & Bradstreet); budget 5–28 days.
- Apple Developer Program: $99/year, same price for Individual or
  Organization.
- Google Play Console: $25 one-time registration.
- The Supabase free tier covers early development and testing; paid tiers
  scale with real usage.
